you want on hand if a scoring question ever comes up.

## The parts that decide the build

**The gate (pass/fail, before any scoring).** Sibyl Memory must be load-bearing:
delete the memory layer and the core function must break. Judged by majority of
the panel; a tie fails. Requires a cold-start recall beat in the demo as one
continuous unedited segment with a visible timestamp or commit hash, plus
critical-path memory calls a judge can find in the repo in under two minutes.

**The rubric (100 pts).** Memory load-bearing 40 · Innovation & originality 25 ·
Technical execution 20 · Pitch & presentation 15.

**PMF bonus (up to +10).** Default is 0. Any nonzero score needs a publicly
verifiable artifact checkable in five minutes. Fabricated evidence is
disqualification, including after payout.

**Partner multiplier.** +15% for the first verified stack, +10% for the second,
capped at ×1.25. A stack counts only when a judge can see it doing real work in
the demo. Base: deployment is the floor, an executed on-chain action earns the
bonus. Virtuals: an ACP job, a registered or transacting agent, or another
Virtuals-native integration exercised in the demo.

**Final score** = (rubric + PMF) × multiplier.

**Submission requires** a public repo under MIT or Apache-2.0 with real commit
history; a 2-5 minute demo including the fresh-session recall beat; a README
covering what it does, where memory is load-bearing, which partner stacks and
where, a "how memory made this possible" note and a Prior Work declaration; and
two public posts tagging @sibylcap and each claimed partner.

**Utility over slop.** Memory used as a trivial notepad passes the gate but
scores at the floor and will not place.
